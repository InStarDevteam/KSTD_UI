# 보안 기준과 운영 전 조치

프레임워크 쿠키 인증/비밀번호 해시, CSRF 토큰, 서버 역할·객체 인가, DTO/ORM, 요청 용량제한, 랜덤 파일 저장명/웹루트 외 저장/인가 다운로드, traceId 오류, 감사이력을 기본 통제로 채택한다. 상세 동작은 API 계약과 통합시험에서 확인한다.

로컬 HTTP는 개발 전용이다. 운영 HTTPS/TLS, Secure 쿠키, HSTS, CSP/프록시/허용 출처를 실제 배포환경에서 확인해야 한다. 와일드카드 credentials CORS를 허용하지 않는다. 개발 seed 비밀번호는 환경변수로 주입하고 운영에서 seed하지 않는다. 자격증명은 저장소·프런트 번들·로그에 넣지 않는다.

첨부는 5MB·3개·허용 확장자/실제형식 제한을 사전 안내한다. 파일 내용을 안전하다고 인증하지 않는다. 백신/샌드박스 엔진은 미연동이며 운영 전 격리·탐지·모니터링·실패 시 차단 정책과 시험이 필요하다. 업로드 문서의 접근성은 별도 검토한다.

CSV는 UTF-8 BOM/필드 인용/줄바꿈 이스케이프와 = + - @ 탭·CR/LF 시작값의 수식 주입 방어를 적용한다. JSON/Markdown은 코드 실행 없이 텍스트로 내보낸다. 외부 URL fetching/리다이렉트 기능은 기본 미제공이며 도입 시 SSRF 재검토한다.

의존성 잠금/실제 audit/라이선스 목록을 보관한다. 고위험 결과는 실제 사용 경로와 조치 증빙을 확인해야 하며 임의 오탐처리를 하지 않는다. 상용 분석기·DAST·운영 침투시험 미실행을 무료 도구 결과로 대체하지 않는다. 회사 통제는 선택한 ASVS5.0/OWASP/KISA/SSDF 참고이며 전체 등급·법적 적합성을 주장하지 않는다.
