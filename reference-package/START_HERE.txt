회사 SW 표준 및 샘플 개발 패키지 v0.1
기준일: 2026-10-20

1. 이 패키지의 현재 상태

회사 표준을 정하고 CODEX가 샘플 SW를 개발하기 위한 적용계획입니다.
현재 패키지에는 구현된 SW, 실제 화면 캡처, 시험 성적, 인증서가 없습니다.
Excel의 구현·검증·증빙 필드는 CODEX 실행과 실제 시험 이후에 채웁니다.
PPT는 적용계획과 구현 후 갱신할 결과보고서 구조를 제공합니다.

2. 가장 먼저 사용할 파일

- CODEX_Implementation_Prompt.txt: CODEX에게 그대로 전달할 상세 실행 지시
- Company_SW_Standards_Register_v0.1.xlsx: 표준별 적용대장과 원문 참조 목록
- Company_SW_Standards_Application_Plan_v0.1.pptx: 회사 공유용 적용계획
- standards_catalog.json: Excel과 보고서의 기준 데이터, 통합 관리행 297개

3. CODEX에 전달하는 방법

작업 프로젝트의 reference-package/ 등에 이 패키지를 압축 해제하십시오.
아래 두 원본 PDF도 CODEX가 읽을 수 있는 references/ 폴더에 넣으십시오.
- 「디지털 정부 UI,UX 가이드라인」 수정본('25.8.).pdf
- 「디지털 서비스 UIUX 가이드라인」변경 대비표(´25.8).pdf

원본 PDF는 이 패키지에 중복 포함하지 않았습니다.

CODEX 입력 예시:

"reference-package/CODEX_Implementation_Prompt.txt를 전체 읽고 실행하세요.
같은 폴더의 standards_catalog.json, 원문 색인, Excel, 적용계획 PPT와
references/의 원본 PDF 2개를 입력 기준으로 사용하세요.
실제로 실행 가능한 샘플 SW를 만들고, 실제 코드·시험결과·증빙으로
Excel과 PPTX 결과보고서를 갱신하세요. 미실행을 통과 처리하지 마세요."

4. 기본 샘플 범위

회사 자체 브랜드의 업무요청·첨부자료·처리현황 관리 웹입니다.
React+TypeScript / ASP.NET Core .NET 10 LTS / EF Core+SQLite 기본안이며,
웹 포트8000, API 포트8001, 실제 서버 인증과 파일DB 영속화를 포함합니다.
기존 확정된 저장소·기술스택이 있다면 CODEX가 먼저 확인하고 존중하도록 했습니다.

화면: 로그인, 홈, 요청목록, 요청상세, 단계형 등록/수정, 관리자 처리,
도움말/접근성 안내, 공통 컴포넌트 갤러리.

5. 목록의 범위와 해석

통합 관리행 297개:
- 표준 운영8, 코딩18, 보안18, MDR확인1
- KRDS에서 채택한 UI 통제128
- KWCAG 2.2 검사기준33
- WCAG 2.2 A/AA 성공기준55
- 포용적 UX 회사목표12
- 검증·운영·보고 회사규칙24

기준안의 적용성: 적용262 / 조건부30 / 해당없음4 / 확인필요1.
이 숫자는 표준 간 중복이 포함된 관리행 수입니다. 단일 인증 준수율의 분모가 아닙니다.
KWCAG33개와 WCAG55개는 관련성만 연결하며 별도로 집계합니다.
회사 코딩/보안 통제는 선택한 공식자료를 실무화한 제안이며,
ASVS 전체 등급이나 MISRA 전체 규칙을 전수 검증한 자료가 아닙니다.

KRDS 원문 보조 목록:
- 번호별 문장 추출후보725개
- 구조 섹션103개
- 번호 없는 상호작용 페이지52쪽
- 원문 편집·해석 확인사항10건

725개는 공식 전체 표준 총수가 아닙니다. 번호 없는 규칙, 예외, 그림/색으로
표시된 등급과 상세 조건은 CODEX가 원본 PDF와 대조해 보완해야 합니다.
출처 색인·원문검토상태를 보존하여 누락을 숨기지 않도록 했습니다.

6. 확인이 필요한 두 가지

MDR: 정식 명칭·발행기관·판본·대상 언어/제품이 아직 확인되지 않았습니다.
MISRA나 EU 의료기기 MDR로 임의 치환하지 않았습니다. 정식 명칭을 제공하면
해당 프로파일을 추가합니다. 확인 전에도 공통 표준 작업은 진행 가능합니다.

사용자 지정 네이버 블로그: 원주소·대체 공개주소·검색으로 본문을 확보하지
못했습니다. 해당 글을 읽은 것처럼 인용하지 않았고, 슈어소프트 공식 STATIC
제품문서와 공식 표준자료로 관련 코딩·검증 내용을 보완했습니다.

7. Excel 사용상의 주의

통합적용대장의 노란색 입력영역에 실제 구현 상태, 자동/수동 검증,
구현 파일, 시험ID, 증빙, 검토자와 검토일을 입력하십시오.
필요한 모든 정보가 없으면 종합판정은 통과가 되지 않습니다.
검토일은 Excel 날짜로 입력하십시오.
회사 편차승인은 외부표준 PASS로 집계하지 않습니다.
표준 정의를 변경할 때는 JSON과 Excel의 변경 이력을 함께 관리하십시오.

8. 구현 후 결과보고서가 갖춰야 할 증빙

표준ID, 화면/기능, 구현파일/컴포넌트, 시험ID, commit, 실행시각,
도구/환경, 실제 결과, 증빙 파일과 검토 기록을 연결합니다.
PPT에는 실제 실행한 화면과 검사 결과만 넣습니다.
자동 접근성 검사 통과만으로 전체 접근성 준수나 품질인증을 선언하지 않습니다.
화면낭독기·모바일·장애 당사자 평가는 실제 수행 여부를 별도로 표시합니다.

9. 기타 파일

source_register.json: 공식자료·첨부·사내 제안의 판본과 출처
krds_source_inventory.json: 번호별 원문 참조 후보
krds_section_index.json: 전체 구조 및 번호 없는 기준 검토범위
krds_interaction_index.json: 상호작용의 원문 위치와 확인할 동작
accessibility_scenarios.json: 실제 보조기술·사용자 과업 시험15개
15개 시험은 대표 과업 시나리오이며 전수 시험표가 아닙니다. CODEX는 구현 후 모든 적용 기준에 자동·수동 시험을 연결하고, 미연결 항목의 시험을 추가해야 합니다.
source_issues.json: 원문 이상과 해석·개정 확인사항10건

본 패키지는 회사 표준을 승인하기 전의 초안입니다.
법령·계약 요구, 공식 표준 요구, 사내 강화목표와 샘플 설계를 구분하십시오.
